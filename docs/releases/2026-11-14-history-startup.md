# 首开速度与历史分页

[使用指南](../usage.md) · [架构](../architecture.md)

旧实现虽然限制页面显示行数，打开话题时仍会先下载全部历史。一次实际会话测量为 64 轮、7,533 条记录、约 16 MB，读取约 1.45 秒；浏览器解析和渲染另计。首次目录扫描旧 JSONL 还用掉约 3.3 秒。Goal 先于正文到达时，也可能短暂显示早已完成的目标。

本次改为：

- 首屏目录先查原生数据库，旧格式兼容发现放到后台一次执行。
- 首次正文取最近两轮；向上浏览时每次再取八轮，保留阅读锚点，失败可重试。
- 合并相同话题的在途请求，取消已切换话题的旧请求；GenUI 和目标自动读取等待当前正文就绪。
- 立即使用会话摘要显示标题和工作区；读取失败结束骨架，提供重试。
- 服务重启后保留已显示内容，同时使旧修订失效，让新服务的较低 revision 能正常替换。
- 用户主动导航或输入后，后台发现旧话题不会抢走当前页面。

同机原生桥接只读试读，新首包约 **373 KB / 203 条 / 2 轮**，正文读取 **45 ms**，目录和模型等启动元数据 **46 ms**。使用真实 Codex 历史的隔离网页预览中，首次内容可见约 **937 ms**，只发起一次正文请求，页面无 JavaScript 错误，也未显示旧的已完成目标。这些是一次本机测量，原生会话在继续增长，并非稳定基准或网络速度承诺。

200 轮虚构数据的 Edge 页面测试同时验证了：首开一次分页、古老消息不挂载、远程翻页不重复提交、阅读锚点偏移约 0.13 px、加载期间新回复只显示一次、错误重试和有界 DOM。另有启动测试覆盖真正重启隔离 HTTP 服务、较低修订回读、取消旧请求、晚到目录与目标展示。测试不运行付费模型任务。

类型检查、158 项自动测试与 22 套浏览器回归通过。最终构建再次验证了启动、步骤折叠和历史分页；实时补发快照保持已显示的内容，不会裁掉手动展开的旧步骤。回退、归档后会拒绝晚到的过期历史，初始化中断的实时连接也会释放订阅。显式加载的历史页会在当前服务内保留，当前实现没有为不同浏览器分别保存历史窗口。

原生记录没有删除。编辑历史仍先读取并备份全量，回退后首屏重新受限；附加运行统计按部分投影合并保留。旧版 legacy 存储缺少原生分页，服务端读取仍可能较慢；当前页内的长工具输出也仍由原生完整返回，原始详情的进一步按需 API 不在此次变更内。

变更前备份为 `backup/2026-11-14-before-history-loading-fix`，另有经过验证的本地 Git bundle。个人会话、认证及测试输出不进入公共仓库。
