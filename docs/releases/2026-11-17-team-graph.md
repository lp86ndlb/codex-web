## 实现行为

- 使用 React Flow 12.12.1，关系图按需加载；现有主题、图标、弹窗动画与右键菜单行为复用。布局是有向图和分组区域，节点可双击进入独立原会话。
- 第一层唯一负责人，默认三层，可增至十层。其他成员有唯一直属上级和分组；拖动只改顺序，改归属必须通过节点菜单。
- 连线可单向、双向或禁止；不允许越级或非直属跨层通信。同层跨组必须取得双方上级意见。
- 审批是右侧面板与 Todo 并列的标签。待审正文展开，历史正文按需查看；卡片保留短标题、小字详情和处理记录。图上自动高亮请求、审核与发送方向，审核/发送使用 CSS 虚线动画，尊重减少动画设置。
- 手动、自动与 AI 风险判断可选。新建会话无论策略如何均需用户批准，默认或指定模型与原生强度在创建前校验。
- 原生旧会话通过单会话凭据的本地 MCP 补充新增工具，不能借此取得网页管理权限。原生新会话使用动态工具。
- 只有实际执行、上级审核或 AI 风险判断调用模型。路由、排布、普通授权和队列状态检查不调用模型。

参考组件官方文档：[自定义节点](https://reactflow.dev/learn/customization/custom-nodes)、[箭头](https://reactflow.dev/examples/edges/markers)、[分组](https://reactflow.dev/examples/grouping/sub-flows)。层级权限、双上级审批和账本由 cweb 自己实现，组件负责绘制与图交互。许可说明见 [React Flow 第三方声明](../../bridge/THIRD_PARTY_NOTICES.md)。

真实 Codex 0.169.0 实测包括：

1. 浏览器批准创建两名新成员，未批准时原生会话数不增加。
2. 原执行成员提出跨组请求，经用户批准，再由原主管和新主管分别判断。
3. 原主管第一次要求澄清测试范围；补充“仅预设文本回执，不代表真实接口核验”后，由原主管使用新的审核工具批准。另一个主管独立批准后才投递。
4. 接收方原生历史只出现一次该消息，并返回确认。旧会话的 MCP 扩展及新会话动态工具均实际工作。
5. 切到 AI 风险策略，另一条直属通信经风险审核通过后投递，随后恢复手动模式。
