# 团队关系图与审批试验

此试验将独立 Codex 会话组织为有层级、分组和通信方向的团队，支持审批、派发及反馈。试验数据与日常工作区隔离。通过验证后，可按[工作区团队模式](team-mode.md)在日常网页逐个开启工作区、加入已有会话；不会自动迁入试验图或派发任务。设计背景见[团队模式方案](research/2026-11-17-team-mode-proposal.md)。

## 独立启动

在已安装依赖的仓库根目录运行：

```bash
npm run team:pilot
```

打开 **http://127.0.0.1:4791/?team=1**。需要其他端口时运行 `npm run team:pilot -- start --port 4792`。脚本不会构建到日常网页的 `bridge/dist`，不会重启日常 cweb，也不会把实际工作区加入试验目录。

| 内容 | 保存位置 |
| --- | --- |
| 新建测试工作区 | `.cache/team-mode-pilot/workspace/` |
| 网页设置、审批记录、投递回执 | `.cache/team-mode-pilot/data/` |
| 独立原生会话库 | `.cache/team-mode-pilot/data/codex-home/` |
| 试验网页构建 | `.cache/team-mode-pilot/ui/` |
| 启动日志 | `.cache/team-mode-pilot/server.log` |

首次启动会从当前 `CODEX_HOME`（未设置时为 `~/.codex`）复制登录文件和模型提供方配置到试验会话库，不复制原会话、数据库、插件或 Skills。私有目录及配置不进入 Git。创建会话本身不调用模型；开始演示和批准投递会调用真实模型，计入当前登录账户用量。登录失败时，应在这个独立会话库中排查，不要替换日常会话库。

查看与停止：

```bash
npm run team:pilot -- status
npm run team:pilot -- stop
```

有轮次仍在运行时，停止命令会提示先到试验网页停止该轮，不会强杀进程。数据保留，再次启动可继续查看。更新试验代码后，先停止试验，再启动重建；运行中重复启动只返回已有入口。

## 验证流程

1. 在顶部切换「对话／团队」，或右键工作区选择「打开关系图」。同一菜单中的「团队模式」可暂停、开启通信。
2. 新团队先申请一名最高负责人，在右侧「审批」页核对后点击「批准创建」。再申请其直属主管和执行成员。可使用设置中的默认模型、强度，也可指定原生 CLI 提供的档位；新增会话始终需要用户批准。
3. 右键节点设置层级、上级与分组。默认三层，可增加至十层；第一层只能有一位负责人，其他成员各属一个直属上级和分组。移动层级时下级一起调整，不能形成交叉归组。
4. 从节点连接点拖出箭头；点击连线选择单向、双向或不通信。不同层级只能直接上下级通信，不允许越级。拖动节点、分组只改变同层顺序，不会改变权限。
5. 新任务在图上高亮对应方向，审核和投递时有轻微虚线动画。点击高亮连线查看侧栏任务；在侧栏点击定位可返回对应关系。已送达短暂标绿，历史记录仍可手动定位。
6. 右侧审批卡片用短标题、较小正文展示。待用户审批的正文默认展开，可修改正文、允许、拒绝或取消未投递请求。已有历史正文原样保留，不通过删改历史来精简显示。
7. 双击成员进入原会话，仍可单独对话、停止和管理。满足三层双向连通且无未处理申请时，可点击「运行演示」验证计算 `7+5` 的逐级回传。

「全部记录」包含历史通信和成员申请，按批次显示；定位历史任务时只额外显示目标卡片。拒绝本身不会唤醒模型。试验自动投递使用只读模式，任务限定文本计算，不接入真实项目或硬件。

### 策略与模型用量

| 选择 | 用户审批 | 上级与风险审核 |
| --- | --- | --- |
| 手动审批（默认） | 每条任务、问题、反馈均由用户批准 | 同层通信仍需相应上级批准 |
| 自动审批 | 允许方向内由确定性规则处理，无单独风险审核轮次 | 同层通信不能跳过上级批准 |
| AI 自主判断风险 | 风险审核无法判断时返回用户 | 发件人的直属上级判断风险；最高负责人自行判断 |

策略切换只影响之后的新通信，已有申请保留原流程。同层、同一上级的通信只审核一次；同层跨组需要双方直属上级分别批准。AI 风险审核与某位上级授权重合时合并为一次。上级认为不清楚时，进入对应原会话补充范围，再由该上级返回判定；用户点击批准不能冒充上级意见。

编辑关系图、查询规则、普通手动/自动授权和排队调度不调用模型。**上级审核、AI 风险判断、实际任务执行会消耗模型用量**；AI 判断不是零成本，也不能保证识别所有风险。新成员申请在任何模式下均需用户确认；勾选默认模型时以批准时设置为准，指定档位若原生模型不支持，会在创建前拒绝。

## 审批与投递规则

| 情况 | 行为 |
| --- | --- |
| 待审批 | 接收方收件箱和原生对话均看不到待审正文 |
| 修改后批准 | 批准绑定修改后的正文摘要与版本，原始请求重试仍会去重 |
| 接收方正在运行、等待用户答复或有排队消息 | 保持等待，当前任务结束后检查；不自动插话 |
| 重复批准或过期页面操作 | 返回已处理/版本冲突，不重复发送 |
| 暂停团队 | 保留请求，停止新投递；已开始的原生轮次可在原会话停止 |
| 取消排队 | 未投递消息停止发送，保留审计记录 |
| 原生响应丢失或投递中退出 | 标为「需核对」，阻止向该接收方继续投递；其他接收方不受此项阻塞 |
| 点击「核对回执」 | 有原生接收凭据才标为送达；找不到记录不会自动重发 |

结果必须关联收到的请求，并回给原发件人。改变权限或归属会让尚未投递的批准失效，要求重新审批；只改名称或位置不会反复审核。已在发送中的请求阻止同时修改关系。审核投递结果未知时也不自动重发；可核对回执，或由原审核会话返回带原请求摘要的判定。

## 实现与边界

- 新会话通过原生动态工具使用 `team_members`、`team_inbox`、`team_propose_message`、`team_review_message`、`team_request_member`。成员职责可从 `team_members` 查询。原有会话不能通过 `thread/resume` 修改动态工具列表，因此用本地 `cweb_team` MCP 补充工具。身份由原生请求或单会话凭据绑定；模型没有用户批准/创建权限，审核工具只能处理分配给自己的请求和正文摘要。
- 管理操作沿用 cweb 的本机地址、会话 Cookie、同源和 CSRF 校验。团队默认关闭；隔离开关拒绝共享会话库及外部工作区。
- 投递复用现有 `Bridge.message` 与提交回执，带独立幂等 ID，通过原生 `turn/start` 追加消息，不直接修改原生历史文件。
- 第一阶段复用原子文件存储 `JsonStore`，限制最多 80 名成员、1,000 条通信与 200 条成员申请。它验证单进程/进程重启场景；断电耐久性、长期日志归档、多实例竞争尚不在本阶段验证范围。正式版再评估事务数据库。
- 空闲时不查询模型；有已批准且忙碌的接收方时每两秒检查。团队状态使用事件刷新，仅有原生任务运行时补充轻量状态读取；不循环调用模型询问是否完成。关系图按需加载，大图只渲染可见节点，动画由 CSS 执行。
- 原会话的文件权限仍由 Codex 控制。审批约束 cweb 的通信通道，不作为同一系统用户下任意高权限进程之间的安全隔离机制。

## 回归检查

```bash
npm --prefix bridge run check
npm --prefix bridge test
CWEB_TEST_DIST=../.cache/team-mode-pilot/ui npm --prefix bridge run test:team
```

`test:team` 包括状态机测试、原生协议模拟、HTTP 权限与浏览器交互，不调用真实模型。真实模型验证需要在独立试验网页按上述流程操作，不能用模拟通过代替。
