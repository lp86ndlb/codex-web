# 迁移复盘与日常维护

## 本次暴露的问题

迁移包中的源码、前端和会话恢复成功，不代表终端安装已经完成。Ubuntu 新机出现过 `cweb: command not found`：缺少 `~/.local/bin/cweb`，且当前终端没有对应 PATH。另一个问题是网页使用包内 `CODEX_HOME`，普通 CLI 使用 `~/.codex`，导致同一工作区的 `/resume` 找不到开发会话。

现已将命令安装、PATH、Bash 补全和工作区会话绑定纳入首次恢复流程与 `cweb doctor`。保留已有配置；相同安装可以重复执行。自动安装未完成时明确报告缺项，仍可通过 `bash cweb` 启动。

## 日常目录与入口

| 位置 | 用途 | 处理方式 |
| --- | --- | --- |
| `bridge/client`、`bridge/server`、`scripts`、`docs` | 源码与维护文档 | Git 管理 |
| `bridge/.data` | 网页设置、附件、待办及本机安装记录 | 私有运行数据，必须保留 |
| `.migration/codex` | 当前迁移会话的原生库 | 名称虽含 migration，仍是正在使用的数据；不能当临时文件删除 |
| `.migration/ready.json`、`manifest.json` | 初次恢复记录及包来源 | 保留作为恢复凭据，不重新导入旧快照 |
| `.runtime` | 已安装的便携 Node/npm/Git | 当前安装依赖，保留 |
| `backups` | 原始迁移快照、交接说明与回退材料 | 私有归档，不上传 Git |
| `.cache`、`bridge/test-results` | 构建、验证日志和截图 | 与运行数据分开；按需整理 |

`cweb` 是日常入口；`codex` 在已绑定的 cweb 工作区共享网页会话库。旧终端执行 `source ~/.bashrc`；已经运行的 CLI 需要退出后重开才能更换环境。其他目录和显式 `CODEX_HOME` 保持原样。`codex-portable` 与 `继续开发会话.sh` 保留兼容用途。

“配置已安装”不代表已有终端已加载。曾出现新 Bash 验证成功，但用户从安装前打开的终端启动 Codex，`/resume` 仍只显示默认库会话的情况。`cweb doctor` 现在会另外核对同工作区正在运行的终端 CLI，发现使用其他会话库时给出提示。验证必须覆盖用户实际进程的环境，不能只清除环境变量后打开测试终端。

在已有终端中立即查看迁移会话：先退出当前 Codex、回到 shell，再在 cweb 根目录运行 `bash codex-portable resume`。此入口明确指定网页使用的库，不依赖 `.bashrc` 是否已加载，也无需改动默认库。以后使用普通 `codex` 时，旧 shell 执行一次 `source ~/.bashrc`；新 Bash 自动加载。运行中的 Codex 不会因为重载 shell 文件就切换会话库。

早期方案只绑定工作区，外部会话由网页按来源聚合；工作区绑定不等于全机所有 Codex 库已合并。`command codex` 可绕过 Bash 函数，但也无法让两个独立库共用历史。

后续验收确认，切换工作区入口仍不能让两个库的会话同时出现在原生 `/resume`。现已提供[原生会话库统一流程](native-history.md)：将空闲来源库的记录事务合入正在使用的主库，保留主库文件和进程，再把默认入口变成同一目录的别名。统一后的验收以两个话题同时出现为准，之前的路由验证不能替代此检查。

## 下一次迁移的验收顺序

1. Git 备份代码；用 SQLite 备份接口和完整 JSONL 行获取当前数据。不要把旧 ZIP 当作最新备份。
2. 在独立目录构建，再打包；不要清空运行中的 `bridge/dist`。保留包校验和。
3. 在空目录恢复，至少验证不同父目录、空格与中文路径。已有数据必须拒绝覆盖。
4. 在**新开的普通 Bash** 中运行 `type cweb`、`cweb doctor`、`cweb status`，确认用户级命令和工作区绑定；不能只用开发 agent 已配置好的环境验证。
5. 访问真实网页地址，检查最近会话、旧消息、附件和待办；在工作区运行 `codex resume`，核对同一个开发会话。仅打开选择器即可验证发现能力，无需发送模型请求。
6. 检查目标电脑的可用窗口尺寸及缩放，测试问答、长输入和字号设置；物理分辨率相同也可能有不同的 CSS 可用空间。

## 升级与回退

前端在隔离构建通过后用 `npm run publish:ui -- 构建目录` 发布，保留旧资源，刷新即可启用。服务端需要重启时等待任务空闲，但不能因此把兼容的前端更新也无限推迟。

本机 shell 改动的原文保存在 `~/.config/cweb/backups`。工作区绑定保存在 `~/.config/cweb/workspaces.json`，生成的函数在 `shell.bash`。需要撤销时移除 `.bashrc`/`.profile` 中的 `cweb shell integration` 标记块并恢复相应备份；不会删除原生历史。已开始使用的安装不要随意移动目录，应从当前数据重新打包。
