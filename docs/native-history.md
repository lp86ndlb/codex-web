# 网页与普通 CLI 共用原生历史

网页可以汇总多个 `CODEX_HOME`，但原生 `/resume` 每次读取一个库。Bash 路由或 `codex-portable` 只能切换库，不能把两份列表统一。验收应确认同一个选择器里同时出现迁移前、迁移后的话题，而不是分别验证两个入口。

## 已统一安装的行为

当默认 `~/.codex` 和 cweb 的 `.migration/codex` 解析到同一个真实目录时，普通 `codex`、网页与便携入口共用会话、分页历史和原生名称。运行 `bash cweb doctor` 查看“原生会话库统一”。同名目录的两个独立副本不算通过。

当前运行主库的位置会保留，避免替换活跃数据库或打断其他任务。默认入口使用目录符号链接，已打开的旧 Bash 也无需加载路由即可使用相同历史。这个安装的 `.migration/codex` 仍是活动数据，不能删除或单独移动。下一次换电脑应从当前数据重新打包；打包器会记录入口别名并在新机重定位。

## 将新电脑已有历史合入迁移库

先备份 Git，检查两个库的来源、账号及运行状态。下列命令首先只生成计划：

```bash
python3 scripts/migration/unify-home.py \
  --source "$HOME/.codex" \
  --target "$PWD/.migration/codex"
```

工具要求同一账号、兼容的数据库结构、无重复会话 ID、源库无活动轮次、目标或排队输入；重复 ID 会直接拒绝，需人工比较历史。源库的终端和后台 daemon 必须先退出；确认其中没有工作在运行后，可用 `CODEX_HOME="$HOME/.codex" codex app-server daemon stop` 停止该库的空闲 daemon。目标主库及网页任务可继续运行。

若停止后仍报告源库进程，检查是否留下 `pid-update-loop` 或网页为该来源建立的空闲 `app-server`。核对其库路径和任务状态后再处理对应进程；不能停止目标主库。工具会在切换前再次检查，防止自动重连时带着旧数据库继续运行。

```bash
python3 scripts/migration/unify-home.py \
  --source "$HOME/.codex" \
  --target "$PWD/.migration/codex" \
  --backup "$PWD/backups/native-home-$(date +%Y%m%d-%H%M%S)" \
  --apply
```

执行时通过 SQLite 备份接口保存两边数据库，合入原 ID、名称、归档状态、工具与分页记录，保持 JSONL 字节和分页偏移不变。当前主库的数据库文件不会被替换。随后原子切换默认目录为主库别名；默认库原目录完整保存在 `original-home`，包含原配置和登录文件，因此备份只能私有保存。

主库的模型、配置和冲突的技能文件继续生效；来源版本保存在备份及冲突清单中。空闲库的历史可以合入，队列、作业、远程控制注册等未知非空状态会阻止操作。工具不会停止任何进程，也不会重放模型请求。合并后还需验证普通 `codex resume`、CLI 内 `/resume` 和真实网页；仅数据库行数相加不足以验收。

## 回退范围

`report.json` 记录切换状态，`source` 与 `target-before` 保存数据库快照，`original-home` 保存来源完整目录。准备阶段失败会保留原目录；事务或目录交换失败会回滚本轮数据库变更。成功后重复运行会识别相同真实目录并退出。

已经在统一库继续对话后，不能直接用旧数据库覆盖主库，否则会丢失之后的消息。需要回退时，先结束相关任务并备份当前库，再根据本次报告恢复或导出新增历史。不要在活跃进程中手动替换 SQLite 文件。
